# f1pred

[![CI](https://github.com/Parikshit06/f1pred/actions/workflows/ci.yml/badge.svg)](https://github.com/Parikshit06/f1pred/actions/workflows/ci.yml)
**[Live forecast →](https://parikshit06.github.io/f1pred/)** ·
**[Method and accuracy →](https://parikshit06.github.io/f1pred/method.html)** ·
[Methodology](METHODOLOGY.md)

Probabilistic Formula 1 forecasts: a learning-to-rank model turned into a
coherent finishing-order distribution, graded walk-forward against the
starting grid, with every forecast committed before its session.

## Why this isn't a standard ML project

- **A race is a ranking, not 20 classifications.** An XGBoost ranker
  (`rank:ndcg`) is trained with one query group per race, so each race teaches
  every pairwise comparison in it, not one "winner" label.
- **Time is the enemy.** Every feature is built only from earlier races, and a
  test proves it by rebuilding features from data that stops at a race and
  checking nothing before it changes. Evaluation is walk-forward. Settings are
  fitted on 2022–23, reported on 2024 onward, and never chosen on the races
  they're graded on.
- **Probabilities you can check.** Scores become one finishing-position
  distribution per race (Plackett–Luce mixed with a Monte Carlo of the race),
  so win ≤ podium ≤ top 5 ≤ top 10 always holds and calibration is measured,
  not assumed.
- **An honest bar.** The starting grid predicts a race well on its own. It gets
  probabilities calibrated the same way as the model's, and every comparison
  carries a race-level bootstrap interval.

## Results

Walk-forward over **63 races** (2024 round 1 to 2026 round 15). Each
race is forecast by models trained only on races before it, with settings
fitted on 2022–23. Paired differences carry a 95% bootstrap interval over
races. Generated by `make backtest` into `reports/backtest.json`.

**After qualifying** (official starting grid known):

| Approach | NDCG@3 | NDCG@5 | Winner | Podium overlap | Win log loss | Podium Brier |
|---|---|---|---|---|---|---|
| **This model** | 0.846 | 0.889 | 57% | 1.92 of 3 | **1.172** | **0.068** |
| Grid order, calibrated | **0.857** | **0.897** | **59%** | **2.05 of 3** | 1.341 | 0.069 |
| Championship order | 0.756 | 0.808 | 30% | 1.68 of 3 | 2.128 | 0.096 |

**Against the grid, nothing is statistically clear.** The model's win log loss
is 0.169 lower (95% interval -0.40 to +0.03) and its NDCG@5
0.008 lower (-0.026 to +0.010); every other interval also includes
zero. Once qualifying has run, a calibrated starting grid captures most of
what can be known. An earlier version of this project reported a much larger
lead (log loss 1.164 against 1.493), but that grid baseline was never
calibrated.

**Where the model clearly adds something:**

| Forecast | Model | No-model reference | Difference (95% interval) |
|---|---|---|---|
| Race, before qualifying: win log loss | **1.775** | 2.128 (championship order) | -0.353 (-0.612 to -0.083) |
| Qualifying: pole log loss | **1.841** | 2.089 (recent qualifying form) | -0.248 (-0.484 to -0.019) |
| Qualifying: NDCG@5 | **0.843** | 0.814 (recent qualifying form) | +0.029 (+0.005 to +0.054) |

**Calibration.** When the model says X%, the average gap to what happened
(expected calibration error, per driver) is 0.7% for wins, 2.6% for podiums
and 5.8% for the top ten. Reliability diagrams are on the
[method page](https://parikshit06.github.io/f1pred/method.html).

## Architecture

```
jolpica ─┐                        ┌──────── temporal feature layer ────────┐
OpenF1 ──┼─→ DuckDB ─→ validate ─→│ every value from earlier races only    │
FastF1 ──┘   (raw_*)              └───────┬───────────────────────┬────────┘
                                          ▼                       ▼
                               qualifying model           race model (XGBRanker,
                            (history + FP1–FP3 pace)       one group per race)
                                          │                       ▲
                               predicted grid ──(before quali)────┤
                                                official grid ────┘ (after quali)
                                                          │
                                                   race scores
                                                          ▼
                          Plackett–Luce  ⊕  Monte Carlo (pace noise, safety car,
                                          │  retirement risk, grid, unknown grid)
                                          ▼
                       one finishing-position distribution per race
                         → win · podium · top 5 · top 10 · expected finish
                                          ▼
                 walk-forward scoring · calibration · website + reports/*.json
```

## Leakage prevention

- Rolling windows shift a whole race before aggregating; team features
  collapse to one value per team per race first, so a driver never sees the
  teammate's result from the same race.
- **Truncation test**: features built from data ending at race *k* equal
  features built from everything, for every race up to *k*. It caught a real
  leak: a season-progress feature divided by the number of races already run.
- **Tampering test**: reversing one race's result moves no feature of that
  race or any earlier one.
- The walk-forward trains on `race_seq < k` only, and a test spies on every fit
  to prove it. Before qualifying, every grid and qualifying input is replaced by
  its projection, so the real result can't reach a pre-qualifying forecast.

## Quick start

```bash
make setup   # exact versions from uv.lock (Python 3.11–3.13)
make demo    # whole pipeline on a synthetic championship: no network, ~1 min
make test    # unit, leakage and end-to-end tests
```

With real data (no API keys needed):

```bash
make data-jolpica SEASONS=2018-2026   # ~15 min first time, rate-limited, cached
make data-openf1                      # official grids and entry lists
make repair validate features
make predict dashboard                # forecast the next race, render the site
make backtest experiments verify      # regenerate reports/*.json
```

## What each piece is worth

`make experiments` writes `reports/experiments.json`. Every experiment is a
walk-forward with race-paired intervals. Choices are made on 2022–23 and
checked on 2024 onward. Experiments fit one seed per model, so their figures
sit slightly off the headline's five-seed ones.

**Calibration and the simulation.** The same out-of-sample scores on 2024
onward, turned into probabilities five ways:

| Probability step | Win log loss | Podium Brier | Calibration error, win |
|---|---|---|---|
| Raw scores (temperature 1, no simulation) | 1.696 | 0.0749 | 4.2% |
| Temperature fitted on 2022–23, held | 1.211 | 0.0668 | 0.5% |
| **Temperature refitted on the last 24 races (in use)** | **1.197** | 0.0674 | 0.8% |
| Refitted, Plackett–Luce only | 1.282 | 0.0713 | 0.7% |
| Refitted, simulation only | 1.245 | 0.0651 | 0.5% |

**Ablation: what adds information once the grid is known.**

- **Everything together vs the grid alone**: log loss 0.956 vs 1.615 on
  2022–23 (difference +0.659, interval +0.342 to +1.019), but 1.220 vs 1.319 on
  2024 onward (not clear).
- **Circuit history** is the one group whose removal clearly hurts ranking
  (NDCG@5 on 2022–23, interval -0.028 to -0.004).
- **Largely duplicates**: driver form, team form, qualifying form and
  qualifying position. Removing any one changes nothing clearly, because the
  others carry the same information. Grid and qualifying position correlate at
  0.95, and the form features at around 0.9 with one another. Qualifying
  position stays in: it is how a car that took a grid penalty is recognised
  as fast.
- **The teammate qualifying gap** added nothing (+0.007, interval -0.047 to
  +0.060) and was taken out of the race model.

**Practice pace (FP1–FP3), only where it belongs.** On the 28 weekends with
practice data, practice improves the qualifying forecast: pole log loss
-0.227 (-0.406 to -0.044), NDCG@5 +0.028 (+0.012 to +0.046). After
qualifying, it adds nothing to the race forecast (log loss -0.019, -0.088 to
+0.057). It feeds the qualifying model only, and the live pipeline fetches just
the current weekend.

**Tested and not adopted.** Median instead of mean recent form: 2022–23 log
loss -0.049 (-0.104 to +0.009), an interval that includes zero. Alternative
XGBoost settings: the ranking of candidates flips between 2021 and 2022–23,
and the settings in use are within noise of the best on both.

## Explainability

Each forecast row opens to show why: SHAP contributions from XGBoost's own
TreeSHAP (`pred_contribs`, identical to `shap.TreeExplainer`). The published
score averages five seeds standardised within the race, so each seed's values
are centred and scaled the same way and averaged. The contributions then sum
exactly to the score that was published (tested). They describe what the model
relied on, not causes.

## Limitations

- Win probabilities are well calibrated; podium and top-10 probabilities run
  over-confident at the top end (a stated 90%+ happened about 85% of the time),
  because the temperature is fitted on winners only. `make verify` flags it.
- Not modelled: weather, tyre and pit strategy, in-race penalties, team orders,
  upgrades, safety-car timing, failures shared by a team's two cars.
- Until the official grid is published, penalties are unknown and the
  qualifying order stands in; the forecast says so.
- About 60 test races separate the model from naive baselines, but mostly not
  from the starting grid.
- The season projection assumes current form holds, widened by a calibrated
  pace-drift term.

## Championship projection

The rest of the season is simulated 10,000 times, sprints included, from each
driver's median score over their last eight real weekends. Every driver with
points stays in the title race, including one sitting out a race. Graded on
27 checkpoints across 7 completed seasons (2019–2025), each projected with a
model trained only on races before it:

- **Who wins**: the favourite was right 89% of the time, Brier 0.074.
  Above 95% it is 14 for 14, but the 95% interval on that runs down to
  0.79, so a published 99.9% means the arithmetic says it's over, not one
  chance in a thousand. The misses are all 2025's Piastri–Norris season (2025 after round 8, 2025 after round 13, 2025 after round 18).
- **How close**: every points total carries a 10th–90th percentile range,
  sized on 2019–22 and graded on 2023–25 (`make calibrate-spread`):

| Projection | Constructors inside the range | Width | Teammate gap inside | Target |
|---|---|---|---|---|
| Race luck only | 56% | 39 pts | 69% | 80% |
| **With the season-long pace term** | **80%** | 96 pts | 72% | 80% |

Constructors land on target. The teammate gap is still short of 80%: on 2019–22
the ranges needed no extra driver term, but on 2023–25 they were too narrow.

## Project structure

```
src/f1pred/
  ingest/            jolpica, OpenF1 (grid, entries), FastF1 (practice pace)
  store.py           DuckDB schema; raw tables never overwritten
  validate.py        22 data checks
  weekend.py         who is in the race, and where each car starts
  features.py        temporal feature layer
  model.py           XGBoost rankers, ensemble SHAP
  probability.py     Plackett–Luce, calibration, one coherent distribution
  simulate.py        Monte Carlo race simulation; forecast()
  predict.py         forecast one race, with provenance
  baselines.py       grid order and other no-model forecasts
  backtest.py        walk-forward, tuning
  metrics.py         ranking and probability metrics, bootstrap
  evaluation.py      headline backtest and experiments
  championship.py    season projection (sprints included)
  verify.py          release gate: leakage, calibration, coherence
  report*.py, method_page.py   the website
  demo.py            synthetic championship for make demo and CI
predictions/         every logged forecast (the track record)
reports/             measured figures; the README is tested against them
tests/               unit, leakage, pipeline (end-to-end on the demo data)
```
